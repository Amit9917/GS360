# Governance

This document describes how decisions are made in GS360 and how contributors can grow into maintainers.

## Project Stewardship

GS360 is maintained by **Jina Code Systems LLP**. The project uses a **Benevolent Dictator For Life (BDFL)** model — the maintainer team at Jina Code Systems has final say on what gets merged, what gets prioritised, and where the project goes.

This model ensures that the project remains focused on its core mission: providing a high-quality, free, open-source UPSC learning platform without the overhead of complex committee voting.

## How Decisions Are Made

| Decision Type | Who Decides | Process |
|---|---|---|
| Bug fix PRs | Any maintainer | Standard code review |
| Content pack PRs | Maintainer team + community | PR review + schema/copyright validation |
| New features | Maintainer team | PR review + discuss if non-trivial |
| Security architecture | BDFL / Security lead | Mandatory review |
| License changes | BDFL | Would require public notice and rationale |
| Releases | Maintainer team | Semantic versioning, accuracy benchmarks passed |

## Contributor Path

1. **Contributor** — Anyone who opens issues, submits PRs (code or content), or participates in discussions.
2. **Trusted Contributor** — Consistent high-quality contributions. Given triage access.
3. **Maintainer** — Invited by existing maintainers based on sustained commitment to the project.

## Commercial Relationship

Jina Code Systems operates a managed version of GS360 at gs360.study. The open-source edition and the managed version share the same core engine. Features developed for the managed platform that benefit the community will be upstreamed to this repository under the same AGPL-3.0 license.

## Fork Rights

This project is licensed under **AGPL-3.0**. You have the right to fork, modify, and redistribute under the same license. One of our goals is to enable anyone to fork GS360 to create specialized learning platforms for other exams (GATE, SSC, NEET, etc.).
